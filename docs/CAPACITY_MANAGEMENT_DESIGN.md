# forkfs 产品规划：本地工作空间、远程备份与集群管理

状态：产品规划草案，待 review。为保持 PR #6 的链接连续性，保留原文件名。
本文描述目标与分期，不是已实现能力或已确定的技术方案。本 PR 仅修改文档。

## 1. 产品定位

forkfs 为开发者及多 Agent 工作流提供可以快速创建、保留和清理的独立工作空间。
用户无需理解底层存储细节，就能知道：

- 工作空间最多可以占多少本地磁盘。
- 当前用了多少、什么时候需要清理、哪些内容可以安全清理。
- 哪些重要版本已备份，以及本机丢失或损坏后如何恢复。
- 多台机器上有哪些工作空间、各节点是否健康，以及任务在哪台机器执行。
- 一个 World 或版本具体改了什么，是否值得保留、备份或交给他人审阅。

核心体验是 **本地容量可控、清理有依据、重要版本可恢复**。
先完善 macOS 本地使用闭环，再扩展远程备份与多机器统一管理，
不把集群管理等同于分布式共享文件系统或多人实时协作。

## 2. 基础功能与付费功能

| 范围 | 产品能力 | 定位 |
| --- | --- | --- |
| 本地工作空间 | 初始化、fork、checkpoint、查看与管理 | 基础功能 |
| 本地容量管理 | 初始化总容量、用量展示、接近上限提醒 | 基础功能 |
| 安全清理 | 清理预览、垃圾状态、用户主动回收 | 基础功能 |
| 本地差异审阅 | 文件变化、版本间比较、逐行文本 diff 与 patch 导出 | 基础功能，已有文件级能力，其他待实现 |
| 远程备份 | 上传选定版本、计划备份、备份历史 | 付费功能 |
| 远程恢复 | 查找恢复点、下载并恢复到本机或新设备 | 付费服务的一部分，已有数据取回不以续费为条件 |
| 集群版 | 节点接入、统一状态、工作空间目录、远程管理与任务跟踪 | 独立产品形态，是否付费及如何打包待确认 |

本地核心功能不要求登录或联网。远程备份必须显式启用，不默认上传用户数据。
具体套餐、价格、远端空间额度与超额规则留待后续商业设计。

## 3. 首次使用：先确定空间边界

用户初始化时选择源项目及分配给 forkfs 的总容量。产品说明这是什么限制、
首次导入是否需要复制、需要哪些权限，再让用户确认，不悄悄改变磁盘布局。
初始化结束后，用户直接进入创建与使用 World 的流程。

按用户 review 意见，**优先实现物理空间硬上限**，而不是只做逻辑软预算。
目标是由文件系统限制受管工作空间继续分配空间，而不只在 forkfs 命令里提醒。
当前优先评估专用 APFS 卷配额；它可能要求全部受管 World 位于指定存储区域。
实现方式、权限和兼容性在后续技术设计验证，若不可行再明确讨论替代方案，
不能静默降级成软限制。

容量上限不等于预留空间：宿主磁盘仍可能被其他应用占满。产品须同时展示
forkfs 容量与宿主可用空间。旧的普通目录模式不被自动迁移，也不能被标为
已经具有硬配额保护。扩容、迁移和存储区域退出流程后续单独设计。

## 4. 日常使用：看得懂的状态与提醒

用户能快速看到总容量、当前占用、可用空间和是否需要采取行动。不把克隆的
逻辑大小简单相加并冒充物理占用；指标暂不可用时明确说明，不显示虚假健康状态。

初步提醒建议：

- 低于 80%：正常展示。
- 达到 80%：建议查看可清理内容。
- 达到 95%：强调空间紧张，建议尽快清理。
- 达到限制或实际空间不足：说明写入失败原因及可行的恢复步骤。

阈值待使用反馈调整。第一阶段在 CLI 使用过程中展示提醒，不承诺常驻后台
实时通知；即便用户不运行 CLI，硬容量限制仍应由底层执行。后续是否增加
菜单栏或桌面通知取决于实际需求。

## 5. 清理体验：先说明，再执行

接近容量时提供清晰的下一步，而不是只打印“请运行 GC”：

1. 预览已到期垃圾、暂不能回收的对象及原因。
2. 有可回收内容时，由用户主动启动清理，并展示进度与结果。
3. 主要占用来自活跃 World、快照或预热池时，引导用户选择不再需要的内容。
4. 没有安全清理对象时明确说明，不能暗示 GC 一定能解决。

不自动删除活跃工作，不为腾空间缩短保留期，不承诺预览字节等于实际释放量。
容量已满时仍应提供可理解的恢复流程，不能陷入“需要清理但无法清理”的死角。

Codex review 指出的约束保留为后续设计门槛：**清理预览必须真正只读**。
当前普通 store 打开可能触发恢复和写入，不能直接复用后宣称零修改；技术方案
必须解决这一点，或明确报告无法安全预览，不偷偷执行恢复。

## 6. 付费远程备份：保护重要版本

### 用户体验

用户开通付费服务后，明确选择要备份的项目或快照，看到上传进度、远端用量、
最近成功恢复点及失败原因。第一阶段以已提交快照为备份单位，不把仍在修改
的 World 默认为已备份，也不暗示所有实时修改都得到保护。

先提供手动备份与完整恢复，再增加计划备份、历史保留和配额提醒。建议优先
评估托管远端，减少配置负担；自带对象存储、团队共享及多区域策略后续再评估。

### 恢复与信任

- 能从备份恢复到新目录或新设备，不默认覆盖已有工作。
- 明确展示“可恢复的版本”，不能把上传请求成功当作备份完成。
- 备份默认不触发本地删除，恢复也不得绕过本地容量限制。
- 加密传输与存储，明确密钥管理及恢复方式；具体安全方案单独设计和 review。
- 不上传未经用户选择的数据，不用备份内容训练或进行与备份无关的处理。

### 付费边界

本地容量和远端备份额度分开展示。远端额度不足时暂停新上传并提示，不默认
产生超额账单或自动升级。价格、计费口径、区域选择与保留期限尚未确定。

到期或取消订阅不影响本地工作；对于仍在约定保留期内的已有备份，允许查看、
下载和恢复，不以续费作为取回数据的条件。保留期及到期删除规则必须购买前
说明并提前通知，不能在本文里擅自设定自动删除期限。

## 7. 集群版：多机器统一管理

### 用户场景与首期范围

面向拥有多台开发机、Mac 节点或 Agent 执行机器的个人与团队，提供一个统一
入口，回答“机器是否在线、空间是否充足、工作空间在哪里、操作是否完成”。
首期支持同一管理域内的 macOS 节点，不因此承诺 Linux/Windows 支持。

- **节点管理**：显式加入、命名/标签、查看版本与健康状态、撤销接入。
- **统一视图**：按节点查看容量、World、快照、备份状态及最近更新时间，
  可以筛选项目与节点，不必逐台登录查看。
- **远程管理**：选择明确节点发起创建工作空间、checkpoint、备份或安全
  清理，跟踪排队、执行、成功、失败与待确认状态；不默认提供任意远程 shell。
- **跨机器恢复**：把已提交的快照通过明确的数据传输或备份恢复到另一节点，
  先检查目标容量及权限；恢复完成不自动删除源数据。

首期由用户选择目标节点；自动调度、负载均衡和自动故障迁移后续再评估。
集群管理不强制所有数据上传云端；节点间传输与付费远程备份的权益边界单独
确认，不把跨机恢复默认为已购买云备份。

### 必须明确的边界

每个节点仍独立存储、独立执行本地硬配额。集群汇总容量只是管理视图，不能
把 A 机器的剩余空间直接用于 B 的写入，也不承诺跨机器 fork 与本地克隆同速。
同一 World 不在多台机器同时共享可写状态；实时同步、共享文件系统和冲突
合并不属于本期集群版。

管理服务或网络不可用时，已有本地工作继续；离线节点显示离线/数据过期，
不显示健康，也不能把未收到结果的远程任务判为成功或自动重复执行。重连后
应核对任务实际状态，避免重复创建或重复清理。

统一管理必须包含最基本的节点认证、访问范围控制和操作记录；不能以首期
功能少为由省略。删除、GC 等操作明确显示目标节点与对象，支持先预览，
遵守节点本地依赖和保留策略。撤销节点接入停止新的远程控制，不擦除本地数据。
复杂企业权限、SSO、跨组织管理和控制服务高可用另行规划。

### 产品形态与商业边界

“集群版”先作为独立产品形态纳入路线图。托管控制服务还是私有部署、按节点
还是按团队收费、是否与远程备份套餐组合，均待确认；目前只有远程备份明确
为付费功能，不据此直接认定所有多机管理都付费。即便组合销售，也须分别
展示节点管理权益和远端存储额度。

## 8. 差异查看与审阅

### 已实现的基础能力

当前 `world fs diff W1` 比较 World 与其记录的基线快照，输出新增、修改、
删除及仅元数据变化的文件；`--stat` 提供汇总。比较涉及文件内容及权限、
xattr 等元数据，已有专门的 diff 测试。参见 [使用说明](../README.md#world-fs-diff)
和 [CLI 实现](../cli/main.cpp)。这些是文件级变化清单，不是逐行文本 diff，
也不是任意两个版本之间的通用比较。

### 目标体验与分期

用户在 checkpoint、备份、清理或交付 Agent 工作成果前，能看懂改动，选择
需要保留的版本，并向他人提供可审阅的结果。

- **本地优先**：支持选择两个 World / 快照进行比较，明确显示双方身份与
  基线；提供目录/文件摘要、逐行文本差异及常规文本 patch 导出。
- **展示增强**：在基础比较稳定后，再评估可视化或外部 diff 工具集成，
  不把图形界面作为首个版本的前置条件。
- **跨机器扩展**：集群版后续支持选择不同节点上的版本或远端恢复点比较，
  明确权限、数据获取范围、传输进度与成本；不能因为已有集群总览就宣称
  已能读取和比较所有节点内容，也不默认上传文件。

### 范围与可信度

差异查看默认不修改比较对象。正在被写入的 World 不保证比较期间内容固定，
应提示结果可能变化；需要可复现审阅时引导使用已提交快照。读取失败或内容
不可用必须明确呈现，不能把“未能比较”显示为“没有变化”。

二进制、大文件、符号链接及权限/xattr 变化采用适合的摘要，不强行显示文本
行差异。patch 导出首期只覆盖明确支持的文本变更，不承诺完整保存权限、
xattr、硬链接或全部文件系统语义；不支持的变化必须列出，避免误以为 patch
能够完整还原一个 World。自动应用 patch、版本合并和冲突解决另行规划，
不因提供 diff 就宣称已有 merge 能力。

本地 diff 与文本审阅属于基础功能，不要求远程订阅；跨节点查看的管理权益
待集群版方案确认，访问远端备份仍遵守数据取回原则。

## 9. 交付阶段与完成标准

| 阶段 | 核心范围 | 完成标准 |
| --- | --- | --- |
| P1 本地容量闭环 | 初始化硬容量、状态、提醒、安全 GC 引导 | 用户可以设定边界、看懂占用并安全处理空间不足 |
| P1b 本地差异审阅 | 任意 World/快照对比、逐行文本 diff、文本 patch 导出 | 用户能识别改动并导出支持范围内的审阅结果，无法比较的内容不误报一致 |
| P2 付费备份 MVP | 显式启用、手动快照备份、历史列表、恢复、基础权益校验 | 完成从本地备份到另一干净环境恢复的闭环 |
| P3 日常备份体验 | 计划备份、失败提示、保留策略、额度管理 | 用户能持续了解保护状态，且不会意外收费或失去取回渠道 |
| P4 集群管理 MVP | 节点接入、统一视图、指定节点操作、基础权限与操作记录 | 至少两台机器可统一管理，断连/重连时状态可信且不重复执行操作 |
| P5 跨节点工作流 | 快照分发/恢复、跨节点版本比较、目标容量检查与传输状态 | 用户能跨节点比较选定版本并安全恢复，不覆盖已有工作或删除源数据 |

以上是建议顺序，暂不承诺日期。集群统一视图与管理本身不依赖付费备份，
可根据多机需求优先级提前；跨节点工作流可复用后续快照传输/恢复能力。
本地差异审阅不依赖备份或集群服务，可作为独立迭代；可视化展示另行排期。
每阶段先有独立技术设计与验收，再开始实现；不把 P1 的本地功能依赖于账号、
支付或远程服务上线。

暂不纳入：自动淘汰用户工作、实时云同步、多人协作合并、跨平台完整支持、
复杂企业权限体系、存量数据无感迁移、分布式共享文件系统和自动任务调度。
基础集群访问控制不在排除范围。后续基于用户需求再排优先级。

## 10. 下一轮需要确认的事项

- 是否接受硬配额可能带来的指定存储区域、首次复制和权限确认。
- 是否认可以本地闭环 → 手动付费备份与恢复 → 计划备份的顺序交付。
- 远程服务是否优先托管，而非先支持用户自带 bucket。
- 集群版是否需要优先于计划备份；首先服务个人多机还是团队共享节点。
- 集群控制服务的托管/私有部署选择，以及独立收费或套餐组合方式。
- 本地差异审阅与容量管理的优先级，以及是否先完成 CLI 再做可视化。
- 套餐、价格、远端额度、保留期和具体技术路线另开设计，不在本轮定死。

已确认方向：硬上限优先；安全预览不能改数据；远程备份属于付费功能；
增加集群版，支持多机器统一管理；在已有文件级 diff 上补齐差异审阅体验。
本轮只 review 产品范围和优先级，不代表底层能力已验证或已批准实现方案。
